# IAReloadingCooldown

Аддон для ItemsAdder (Paper 26.3, Java 25). Добавляет `indicator: RELOADING`: во время перезарядки
предмет в инвентаре затемняется ванильной шторкой, как хорус, эндер-жемчуг или щит после удара топором.
Пока идёт перезарядка, `events` предмета не выполняются.

```yaml
    events_settings:
      cooldown:
        indicator: RELOADING
        ticks: 300
        # group: cat_buffs   # необязательно: общая перезарядка для нескольких предметов
```

Если ItemsAdder ругается на неизвестный `indicator`, есть запасной вариант. Аддон работает с ним так же:

```yaml
      cooldown:
        indicator: HIDDEN
        reloading: true
        ticks: 300
```

## Установка
Скачайте `IAReloadingCooldown-1.0.0.jar` из [Releases](../../releases) и положите в `plugins/`.
Нужны Paper 26.3 и ItemsAdder.

## Сборка
```
./gradlew build
```
На Windows: `gradlew.bat build`. Готовый jar появится в `build/libs/`. Нужен только JDK 25:
нужную версию Gradle (9.9.1) wrapper скачает сам.

## CI
GitHub Actions собирает jar на каждый push и pull request. Jar можно скачать во вкладке Actions,
в артефактах запуска. При push тега `v*` jar прикрепляется к релизу с этим тегом (если релиза нет, он создаётся).

## Команды (`iareloading.admin`)
- `/iareloading info`: список RELOADING-предметов и число обработчиков ItemsAdder под контролем аддона
- `/iareloading reload`: перечитать конфиги (после `/iareload` это происходит само)
- `/iareloading clear <игроки>`: сбросить перезарядки

## Как работает
- **Шторка.** На предмет ставится ванильный компонент `use_cooldown` с отдельной группой
  `iareloading:<namespace>/<id>`. Поэтому затемняется только этот предмет, а не все `IRON_SWORD`.
- **Блокировка.** Аддон оборачивает обработчики событий ItemsAdder. Пока предмет на перезарядке,
  ItemsAdder не получает событие, и его действия не выполняются.
- **Отслеживаемые триггеры:** `interact` / `interact_mainhand` / `interact_offhand`
  (`right`, `left`, `right_shift`, `left_shift`, `entity`), `attack`, `eat`, `drink`, `drop`, `bow_shot`, `item_throw`.
  Остальные триггеры (`held`, `kill`, `block_break` и т.д.) перезарядку не запускают и не блокируются.

## Граничные случаи
- **Выход и вход, рестарт.** Время окончания пишется в PDC игрока в момент старта. Перезайти, чтобы сбросить КД, не получится.
- **Смена мира, смерть и респавн.** Клиент теряет шторки, аддон отправляет их заново через 1 тик.
- **`/iareload`.** Конфиги перечитываются асинхронно, слушатели оборачиваются заново. КД удалённых предметов снимаются, остальные отправляются повторно.
- **ПКМ по сундуку, двери, кнопке и т.п.** Без шифта клик уходит в блок, как в ваниле: перезарядка не запускается. С шифтом (или если открыть блок запрещено) клик считается использованием предмета.
- **Двойной клик (блок + воздух).** Второе событие того же типа блокируется. Разные события одного броска (launch + projectile) проходят оба.

## Производительность
- Ни одной повторяющейся задачи. Истёкшие записи удаляются при обращении к ним.
- Решение принимается один раз на событие и кэшируется, сколько бы обработчиков ItemsAdder его ни слушали.
- Сначала префильтр по материалу (EnumSet), API ItemsAdder вызывается только при совпадении.
- Конфиги сканируются асинхронно. Файлы без `RELOADING`/`reloading` YAML-парсер не трогает.
